Prisma + Supabase 知识与排障记录

1. Prisma 与 Supabase 是什么

1.1 Prisma（ORM）

  • Prisma 是一个面向 TypeScript/Node.js 的 ORM 工具。
  • 作用是用统一的 Schema 和类型安全的 API 来读写数据库，减少手写 SQL 的心智负担。
  • 在本项目里，Prisma 主要负责：
  • 定义数据模型（如宝宝信息、成长记录、会话、消息）
  • 生成类型安全的数据库访问代码（Prisma Client）
  • 执行迁移或结构同步（migrate/db push）

1.2 Supabase（托管 PostgreSQL + BaaS 能力）

  • Supabase 提供托管的 PostgreSQL 数据库，以及鉴权、存储、实时等能力。
  • 官网：https://supabase.com
  • 在当前阶段，我们主要使用它的 PostgreSQL 数据库能力，先把后端 CRUD 跑通。
  • 后续可按节奏接入：
  • Supabase Auth（用户登录体系）
  • RLS（行级权限控制）
  • Storage（文件上传）

1.3 为什么组合使用 Prisma + Supabase

  • Supabase 提供稳定的云端 PostgreSQL 与运维托管能力。
  • Prisma 提供更好的开发体验（类型安全、模型集中管理、迁移流程）。
  • 两者组合能兼顾「工程效率」和「线上可用性」，适合当前从原型走向产品化的阶段。

2. 本项目当前技术栈定位

  • ORM：Prisma
  • 数据库：Supabase PostgreSQL（云端）
  • 目标：先完成后端接口最小闭环，再逐步替换前端 localStorage 持久化

5. 今日遇到的问题与处理

问题 1：bash: prisma: command not found

原因：

  • 直接执行了 prisma，本地 PATH 中没有全局 Prisma CLI。

处理：

  • 使用 npx prisma ... 调用项目内 CLI。

问题 2：TypeError: (0 , _config2.env) is not a function

原因：

  • prisma.config.ts 使用了与当前版本不兼容的 env() 写法。

处理：

  • 改为 process.env.DATABASE_URL ?? ""。

问题 3：npx prisma generate 报 EPERM / 引擎下载问题

现象：

  • Prisma 引擎下载或缓存写入受限，出现权限或网络错误。

处理：

  • 在可用网络环境执行。
  • 必要时清理/检查本机缓存目录权限（~/.cache/prisma）。
  • 保持 npx prisma generate 可成功后再继续迁移命令。

问题 4：Schema engine error（连 Supabase 时）

可能原因：

  • 网络/代理限制（DNS、端口、代理冲突）
  • 连接串格式问题（密码特殊字符、SSL 参数缺失）

已做处理：

  • DATABASE_URL 增加 sslmode=require
  • 校验连接串可被 URL 解析
  • 使用 npx prisma 链路验证 CLI 可用

待继续验证：

  • 在本机无网络限制环境执行 npx prisma db pull / db push

6. 排障建议顺序（最短路径）

  1. npx prisma -v（确认 CLI）
  2. npx prisma generate（确认引擎）
  3. npx prisma validate（确认 schema）
  4. npx prisma db pull（确认连通）
  5. npx prisma db push 或 migrate dev（确认落库）

7. 下一步建议

  • 先保证 db pull/db push 在你本机网络可稳定通过。
  • 通过后立刻进入接口实现：
  • GET/PUT /api/v1/babies/:babyId
  • GET/POST /api/v1/babies/:babyId/growth-records
  • 再推进会话和消息持久化接口。
